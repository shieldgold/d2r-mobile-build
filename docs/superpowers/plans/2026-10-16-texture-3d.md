# BOTW 普通三维纹理适配计划

目标：处理固定原游戏在 `dc9cfa6` 普通运行中出现的 target2/3D、4×4×1、单mip、format25、flags0、raw samples0 的零大小查询；保留随后 texture=-1/sampler257 的索引拒绝。两个事件的具体因果尚未证明。沿用已授权的 D2R 原生 ARM64 与宿主薄适配架构，不修改游戏文件、Guest框架或通用对象门禁。

架构：继续复用完整 vendor layout、texwrite、deswizzle 和 flush 模块，按固定 base-v0 合同接入普通3D。CPU元数据的支持范围由原SDK和完整上游交叉证明；GPU首域限定普通精确颜色、flags0/raw samples0、depth1/levels1，创建真实 `MTLTextureType3D`，不投影成2D。virtual、多mip、多depth、格式重解释、RT/present等GPU扩展须另有证据，不能随首域静默放行。packaged参数必须独立核对，不能把一维数组的无效H规则套到3D。

技术栈：现有 Objective-C/Metal 图形桥、原 C 布局模块、Python unittest、自有 CPU/Metal 夹具、固定提交普通 Mac 前端及 iOS 通用宿主。本计划按用户既有继续开发并安装到当前手机的授权执行，不再等待重复选择或许可。

## Task 1：固定原始合同和支持边界

- [x] kernel peer 核原 target2 的维数、mip缩小、tileH/tileD、size/alignment、packaged参数，以及 Write/Read 的 z/depth与空域语义；保留可定位的磁盘静态证据及摘要，不读取运行guest对象或扫描VM。自有vendor CPU81组布局组合通过，actual Size/Align均512；此项不是原字节执行或GPU验收。
- [x] graphics owner 对照两个固定完整上游，优先调用完整模块，记录可直接复用部分与版本差异。linear peer 核 Metal/MSL 的真实3D类型、采样与view域，29来源SHA稳定；区分设备API能力和真实GPU验证。
- [x] 明确metadata/GPU支持范围和回归影响：metadata三轴≤2048、合法mips；packaged W/H/D全0，GPUdepth1/level1及既有ordinary精确颜色条件。多depth writer原语义尚未完全证明，首批不扩。没有为后继dummy targets扩大运行guest读取或扫描。

## Task 2：真实失败与最小适配

- [x] 现有fixture已复现编译成功后的Size/Align/Init三项真实失败，另有零诊断layout字段真实RED；无新测试文件或CI路径，原编译误差单列。
- [x] `texture_family.inc`复用完整模块按原3D计算meta与布局，实际4×4×1 Size/Align512；`graphics.m`与dc逐字节不变。
- [x] GPU首域真正分配3D资源并接通公开上传、采样、同维精确view及CPU/GPU authority；拒绝边界在资源创建和发布前执行。空region先验证对象、View、region，再不搬payload；零extent不为坏对象或负数提供豁免。
- [x] 保持通用get/put/Finalize、索引guard、private authority、pool generation和现有各维度合同。任何unsupported不制造dummy资源或假成功。
